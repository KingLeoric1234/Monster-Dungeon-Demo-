\section{Enemy}

\subsection{Module Description}

\par \hspace{1.5em} The system is divided into the following modules.

\begin{itemize}
  \item Spawn Enemy: The only entry point for other modules to send spawn messages.
  \item Public Config: Stores the enemy's static template data.
  \item Public Script: Stores the monster's public behaviour (the Core Pipeline).
  \item Special Enemy AI: Stores the special enemy AI scripts. These scripts modify the core pipeline to change behaviours.
  \item EnemyMessageBus: Provides a private message bus for the enemy system's internal use.
\end{itemize}

\subsection{System Pipeline}

\begin{enumerate}[label=Step \arabic*:, leftmargin = 5em]
	\item A module sends a spawn message to the spawn module. The message contains: monster species, count, and locations.
	\item The Enemy Spawn Module subscribes to spawn messages; EnemyPipelineController.cs begins to control the pipeline.
	\item Initialize the matching template data.
	\item Create a Prefab with the correct Unity components: SpriteRenderer, CircleCollider2D/3D, Rigidbody2D/3D.
	\item Public scripts attach to the Prefab and control the monster's behaviour (the Core Pipeline, described in Section~\ref{sec:pipeline}).
	\item If the monster carries a special function, the matching Special Enemy AI script modifies the core pipeline to change its properties.
	\item Add the sprites and animations, then transmit the Prefab to the Enemy Spawn Module.
	\item The Enemy Spawn Module sends the Prefab to the renderer.
\end{enumerate}

\subsection{Core Pipeline}\label{sec:pipeline}

\subsubsection{EnemyHealth}

\par \hspace{1.5em} \textbf{Core Data (currentHealth):}

\begin{enumerate}
	\item \texttt{\bs Assets\bs EnemyUnit\bs PublicScript\bs EnemyInit.cs}: Data Initialization Region. Copies the template data into EnemyHealthData.cs, which maintains the ``currentHealth'' field.
	\item \texttt{\bs Assets\bs EnemyUnit\bs PublicScript\bs EnemyHealthData.cs}: Maintains the ``currentHealth'' data.
	\item \texttt{\bs Assets\bs EnemyUnit\bs PublicScript\bs Direction.cs}: Receives and calculates damage. The only entry point that accesses ``currentHealth'' in EnemyHealthData.cs. The submodule's introduction is placed in Appendix~\ref{app:c:enemy-movement}.
	\item \texttt{\bs Assets\bs EnemyUnit\bs PublicScript\bs EnemyDeath}: Destroys the EnemyPrefab and plays the death animation.
\end{enumerate}

\par\textbf{Plugs (Relative Path):}

\begin{enumerate}
	\item\texttt{\bs ..\bs Buff\bs EnemyBuffSystem.cs}: The ``DamageBuff'' — only handles debuff damage dealt by the player.
	\item\texttt{\bs ..\bs HealthBar}: The enemy's health bar controller.
	\item\texttt{\bs ..\bs Effects}: Controls various effects, such as hit effects and particle effects.
	\item\texttt{\bs ..\bs Protects}: Guards against unexpected runtime incidents, such as the renderer getting stuck or enemy prefabs getting stuck in walls.
	\item\texttt{\bs ..\bs DamagePopUp}: Damage numbers that pop up when the player deals damage to the enemy.
\end{enumerate}

\par\textbf{Resources:}
\begin{enumerate}
	\item ``HitParticlePrefab'', controlled by HitParticle (\texttt{\bs ..\bs EnemyHealth\bs Effects\bs HitParticle}).
	\item ``EnemyPrefab'', located at \texttt{\bs Assets\bs Resources\bs Enemy\bs EnemyPrefab}.
	\item ``DamageNumberPrefab'', controlled by the DamagePopUp plug (\texttt{\bs ..\bs EnemyHealth\bs DamagePopUp}) (instantiated by scripts).
\end{enumerate}

\subsubsection{EnemyAttack}

\par \hspace{1.5em}\textbf{Attacks are triggered only by Collider2D}. When the enemy's Collider2D touches the player's collider, the enemy sends attack data to the player's ``PlayerHealth'' module.

\subsubsection{EnemyMovement}

\par \hspace{1.5em} Relative Path: \texttt{\bs Assets\bs EnemyUnit\bs PublicScript\bs EnemyMovement}

\par \textbf{Core Data:}

\begin{enumerate}
	\item\texttt{\bs ..\bs EnemyMovementInit.cs}: Initializes the movement data into EnemyMovementData.cs.
	\item\texttt{\bs ..\bs EnemyMovementData.cs}: Maintains the movement data — ``current direction'' and ``current speed''.
	\item\texttt{\bs ..\bs EnemySpeedCalculator.cs}: The only port that controls the current speed. Calculates the final speed and transmits the CurrentSpeed data into EnemyMovementData.cs.
	\item\texttt{\bs ..\bs Direction}: The only port that controls the current direction. Calculates the final direction and transmits the CurrentDirection data into EnemyMovementData.cs.
\end{enumerate}

\par \textbf{Plugs:}
\begin{enumerate}
	\item\texttt{\bs ..\bs EnemyKnockBackApplier}: Controls the enemy's knockback.
	\item\texttt{\bs ..\bs PathFindingAlgorithm}: Controls the enemy's direction, guiding enemies along the correct path to catch the player.
\end{enumerate}
